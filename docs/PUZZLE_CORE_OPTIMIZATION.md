# 光影拼图核心玩法优化记录

## 优化目标

本轮优化来自 2026-07-28 的核心玩法健全性检查，范围限定为拼图棋盘规则、自动组合、玩法状态机和运行资源生命周期。大厅、关卡内容、视觉设计和资源 UUID 不在本轮调整范围内。

## 基线结论

- 完整 `npm run verify` 通过。
- 90 关配置均有效，开局不存在已完成关卡或预连接组合。
- 玩家拖拽规划已覆盖边界、组合移动、死局和连续置换压力测试。
- 实际 Web Mobile 冒烟已验证进入游戏、真实拖拽、超时失败、重玩、返回大厅、加时和查看原图，控制台无红色错误。
- 自动组合在全部 90 关都会提前停滞；3×3 关卡通常只能执行 2 次。
- 胜负判定依赖 View 提供的连接编号，控制器没有独立持有棋盘规则真相。
- 玩法缺少显式暂停和销毁状态，控制器状态流转没有自动化覆盖。
- 拼图节点重复创建销毁，部分业务计时器没有 owner。

## 执行记录

### 阶段一：收拢棋盘规则与胜负判定

- 状态：已完成（2026-07-28）
- 目标：由纯规则域持有棋盘排列、连接组合、进度和完成判定。
- 实现：新增纯规则 `PuzzleBoard`，统一持有排列、反向索引、正确连接组合、进度和完成判定；`PuzzleGameController` 只接受棋盘生成的移动结果；`UIGamePanel` 不再维护或上报另一份可写棋盘状态。
- 测试：新增 6 个纯规则用例，覆盖非法排列、初始组合、原子移动、过期计划、完整通关和重置。
- 验证：`npm run verify:puzzle-rules`、`npm run typecheck`、`npm run verify` 全部通过；完整验证包含 90 关配置、31023 次 9×9 边界落点、5000 次真实连接组压力拖拽、5720 个死局检查和 2000 次连续拖拽。
- 提交：`refactor: make puzzle board authoritative`。

### 阶段二：重写自动组合

- 状态：已完成（2026-07-28）
- 目标：自动组合与玩家拖拽共用移动规划，每次使用必须严格推进，完成前不得停滞。
- 实现：规则域以当前最大正确组为基准，必要时先对齐到原图绝对位置，再吸收一个原图相邻的外部组合；所有步骤复用 `PuzzleMovePlanner` 并先在棋盘副本中完整预演，正式提交后校验结果一致。
- 进度保证：每次使用后最大正确组成员数必须严格增长；完成后再次调用返回空结果，不重复修改棋盘。
- 验证：全部 90 关共执行 426 次自动组合并全部还原，包含唯一 9×9 关；`npm run verify` 全部通过，既有 31023 次 9×9 拖拽边界和 5000 次真实连接组压力回归未受影响。
- 提交：`fix: guarantee auto merge progress`。
