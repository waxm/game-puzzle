# 光影拼图核心玩法优化记录

## 优化目标

本轮优化来自 2026-07-28 的核心玩法健全性检查，范围限定为拼图棋盘规则、自动组合、玩法状态机和运行资源生命周期。大厅、关卡内容、视觉设计和资源 UUID 不在本轮调整范围内。

## 基线结论

- 完整 `npm run verify` 通过。
- 90 关配置均有效，开局不存在已完成关卡或预连接组合。
- 玩家拖拽规划已覆盖边界、组合移动、死局和连续置换压力测试。
- 实际 Web Mobile 冒烟已验证进入游戏、真实拖拽、超时失败、重玩、返回大厅、加时和查看原图，控制台无红色错误。
- 自动组合在全部 90 关都会提前停滞；3×3 关卡通常只能执行 2 次。
- 胜负判定依赖 View 提供的连接编号，控制器没有独立持有棋盘规则真相。
- 玩法缺少显式暂停和销毁状态，控制器状态流转没有自动化覆盖。
- 拼图节点重复创建销毁，部分业务计时器没有 owner。

## 执行记录

### 阶段一：收拢棋盘规则与胜负判定

- 状态：已完成（2026-07-28）
- 目标：由纯规则域持有棋盘排列、连接组合、进度和完成判定。
- 实现：新增纯规则 `PuzzleBoard`，统一持有排列、反向索引、正确连接组合、进度和完成判定；`PuzzleGameController` 只接受棋盘生成的移动结果；`UIGamePanel` 不再维护或上报另一份可写棋盘状态。
- 测试：新增 6 个纯规则用例，覆盖非法排列、初始组合、原子移动、过期计划、完整通关和重置。
- 验证：`npm run verify:puzzle-rules`、`npm run typecheck`、`npm run verify` 全部通过；完整验证包含 90 关配置、31023 次 9×9 边界落点、5000 次真实连接组压力拖拽、5720 个死局检查和 2000 次连续拖拽。
- 提交：`refactor: make puzzle board authoritative`。

### 阶段二：重写自动组合

- 状态：已完成（2026-07-28）
- 目标：自动组合与玩家拖拽共用移动规划，每次使用必须严格推进，完成前不得停滞。
- 实现：规则域以当前最大正确组为基准，必要时先对齐到原图绝对位置，再吸收一个原图相邻的外部组合；所有步骤复用 `PuzzleMovePlanner` 并先在棋盘副本中完整预演，正式提交后校验结果一致。
- 进度保证：每次使用后最大正确组成员数必须严格增长；完成后再次调用返回空结果，不重复修改棋盘。
- 验证：全部 90 关共执行 426 次自动组合并全部还原，包含唯一 9×9 关；`npm run verify` 全部通过，既有 31023 次 9×9 拖拽边界和 5000 次真实连接组压力回归未受影响。
- 提交：`fix: guarantee auto merge progress`。

### 阶段三：补齐状态机与玩法测试

- 状态：已完成（2026-07-28）
- 目标：加入 `idle`、`running`、`paused`、`success`、`failure`、`disposed` 状态以及前后台暂停恢复。
- 实现：控制器以显式状态统一限制移动、自动组合、超时、重开和销毁；游戏场景监听应用隐藏与恢复，只恢复本次后台切换实际暂停的同一控制器；面板计时、预览倒计时、拖拽和道具均服从控制器状态。
- 测试：新增 6 个控制器用例，覆盖幂等开始、暂停恢复、成功后重复输入、失败后重复输入、成功/失败后重开、销毁后永久拒绝恢复和事件监听清理。
- 验证：`npm run verify:puzzle-controller`、`npm run typecheck` 和完整 `npm run verify` 全部通过。
- 提交：`feat: add puzzle gameplay state machine`。

### 阶段四：修正生命周期与对象复用

- 状态：已完成（2026-07-28）
- 目标：所有业务计时器绑定 owner，拼图节点通过 `PoolManager` 复用并在退出时回到基线。
- 实现：新增 `puzzle.piece` 具名对象池和集中资源键；`PuzzlePiece` 通过 `reuse/unuse` 幂等恢复与清理切图、输入和回调；面板重玩时回收节点，场景退出时清空对象池；预览和延迟释放计时器全部绑定 owner。
- 自动化：新增生命周期验证，覆盖真实 `PuzzlePiece` 的首次取出、回收、同节点复用、监听数量、切图清空、池统计、Prefab 句柄释放，以及 Inspector 子组件引用失效后的安全销毁。
- 实际冒烟发现并修复：
  - Creator 旧浏览器兼容编译不能可靠展开 `Set` 函数参数，曾导致自动组合锚点变为 `Infinity`；现改用组合稳定编号，并加入源码兼容回归。
  - 对象池节点销毁时曾重复执行会访问 Inspector 子组件的 `unuse`；现将回池清理与最终销毁清理分开，退出大厅不再出现引擎错误。
- 真实流程：非 Debug Web Mobile 产物已完成 `Boot -> Lobby -> Game`、自动组合严格推进、成功结算、失败后重玩、对象池复用和 `Game -> Lobby` 清理验证；最终一轮控制台无警告或错误。
- 屏幕检查：`375×667` 短屏和 `430×932` 长屏下，关卡标题、进度、时间条、完整棋盘、三个道具入口和操作说明均完整可见。
- 验证：`npm run verify:puzzle-lifecycle`、`npm run verify:puzzle-rules`、`npm run typecheck` 和完整 `npm run verify` 全部通过。
- 构建器说明：Cocos Creator 3.8.4 CLI 在刷新完整产物后仍返回退出码 `36`，日志没有脚本、资源或构建任务错误；生成的 `settings.json` 明确为 `web-mobile`、`debug: false`，并已由浏览器真实运行验证。
- 提交：`perf: pool puzzle pieces and clean lifecycle`。
